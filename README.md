# 🛡 Lighter Guardian

Страж для позиций на **Lighter RH (Robinhood Chain)** и **основном Lighter**. Подстраховывает стоп-лоссы, которые «не сработали», и убирает висящие ордера.

> Это не бот-сервис: каждый запускает **свою копию** со **своим** API-ключом. Никому не отправляй свой ключ — в том числе в «удобные» боты.

## Зачем

Частая жалоба: *«стоп-лосс не сработал»*. Обычно причина одна из трёх:

1. **Стоп сработал, но биржа его отменила.** У стоп-заявки есть «худшая цена исполнения». Если в стакане нет ликвидности по такой цене (на тонких pre-IPO это норма), заявка отменяется, а позиция остаётся открытой.
2. **Стоп считается по mark price, а не по цене в стакане.** На pre-IPO mark может отставать: по стакану цена давно за стопом, а триггер так и не сработал. Стоп-лимит может сработать, но повиснуть неисполненным, если цена убежала дальше лимита.
3. **TP и SL поставлены отдельно, а не связкой.** После стопа тейк остаётся висеть и потом срабатывает на новой позиции.

## Что делает страж

| # | Ситуация | Что делает |
|---|---|---|
| 1 | Позиция закрылась (стоп, тейк, вручную) | Отменяет оставшиеся TP/SL и reduce-only ордера по этой паре. Входные ордера (лимитки, стоп-входы, ордера, ждущие родителя) не трогает |
| 2 | Стоп сработал, но биржа его отменила | Сразу закрывает позицию рыночной reduce-only заявкой |
| 3 | Цена в стакане за стопом N секунд, а стоп не исполнился | Закрывает позицию рыночной reduce-only заявкой |
| 4 | Позиция без стоп-лосса | Предупреждает в Telegram (один раз) |
| 5 | **Вилка RH ↔ CORE**: одна нога закрылась | Сразу закрывает вторую ногу |
| 6 | **Вилка RH ↔ CORE**: одна нога уменьшилась | Подрезает вторую в той же пропорции |

### Вилка (хедж) RH ↔ CORE

Если **в одном кошельке** на Lighter RH и на основном Lighter открыта **одна и та же акция в противоположные стороны** (например, лонг NVDA на RH и шорт NVDA на CORE), страж сам считает это вилкой и пишет «🔗 Вижу вилку».

- **Одна нога закрылась** (по стопу, тейку, ликвидации или вручную) → вторая закрывается рыночной reduce-only заявкой. Так ты не остаёшься с голой позицией.
- **Одна нога уменьшилась** → вторая подрезается в той же пропорции. Закрыл 75% лонга на RH → закроется 75% шорта на CORE.
- **Доливка** не трогается: страж просто запоминает новый размер.
- Тейк или стоп часто исполняется кусками. Страж ждёт, пока куски закончатся (`HEDGE_DEBOUNCE_SEC`), и подрезает одним разом.
- Свои подрезки страж не зеркалит обратно, так что цепочки «подрезал → в ответ подрезал» не будет.
- Ноги вилки без стопа не считаются «голыми»: вилка сама себе хедж.
- Одна акция под разными тикерами (SKHYNIX на CORE и SKHY на RH) распознаётся.

Для вилки у кошелька нужны ключи **обеих** бирж (`W1_RH_…` и `W1_CORE_…`). Позиции разных кошельков в вилку не связываются. `/pairs` в Telegram показывает текущие вилки.

Если закрываешь вилку руками, закрой одну ногу, и страж закроет вторую сам. Если хочешь управлять ногами по отдельности, сначала отправь `/pause`.

Закрытие делается с допуском 1% от лучшей цены. Если не исполнилось, повтор с 2% и 3%. Если и так не вышло, приходит громкий алерт «закрой вручную». Все заявки стража **reduce-only**: открыть новую позицию или перевернуть текущую он не может физически.

Каждый сценарий настраивается: `act` — действовать, `alert` — только сообщать, `off` — выключить.

### Режим проверки (DRY_RUN)

По умолчанию `DRY_RUN=true`: страж ничего не отправляет на биржу и только пишет в Telegram, что **сделал бы**. Поработай так день-два, посмотри на сообщения, и только потом ставь `DRY_RUN=false`.

## Установка

Нужен Python 3.10+.

```bash
git clone https://github.com/<этот-репозиторий>.git
cd lighter-guardian
pip install -r requirements.txt
cp .env.example .env
```

### 1. Кошельки и API-ключи

Страж следит сразу за несколькими кошельками. Каждый кошелёк получает номер (№1, №2, …), и в сообщениях всегда видно, о каком речь: `NVDA · #1 Основной RH`.

Кошелёк на Lighter RH и на основном Lighter один и тот же, поэтому адрес указывается один раз, а номера аккаунтов на обеих биржах страж найдёт сам.

Ключи для кошелька создаются **у тебя на компьютере** одной командой, сразу для обеих бирж:

```bash
python setup_key.py --wallet 1 --name Основной      # кошелёк №1: RH + CORE
python setup_key.py --wallet 2 --name Второй        # кошелёк №2
python setup_key.py --wallet 3 --only rh            # кошелёк №3, только RH
```

Скрипт попросит приватный ключ кошелька (ввод скрыт). Он нужен один раз, чтобы подписать регистрацию API-ключей, и никуда не сохраняется. В ответ скрипт выдаст готовые строки `W1_…` для `.env`.

- Индекс выбирай такой, который больше нигде не используешь (4–156 или 158–254, по умолчанию 4). Старый ключ с этим индексом перестанет работать.
- Нужен субаккаунт, а не основной аккаунт? Флаги `--rh-account` / `--core-account`.
- **Что может API-ключ:** торговать и отменять ордера. Вывод средств возможен только обратно на твой же кошелёк, перевести деньги на чужой адрес им нельзя. Но торговать им можно, так что храни его как пароль.
- Если твой кошелёк — Robinhood Wallet без доступа к приватному ключу, этот скрипт не подойдёт. Смотри раздел [API keys](https://apidocs.lighter.xyz/docs/api-keys) в документации Lighter.

### 2. Telegram

Создай своего бота у [@BotFather](https://t.me/BotFather), впиши токен в `TG_TOKEN`. Свой chat id (узнать у [@userinfobot](https://t.me/userinfobot)) впиши в `TG_CHAT_ID`, потом напиши своему боту `/start`.

Команды бота:
- `/status` — позиции, стопы, тейки, цены, вилки (`/status 2` — только кошелёк №2);
- `/pairs` — вилки RH ↔ CORE (`/pairs 1` — кошелька №1);
- `/wallets` — список кошельков и аккаунтов;
- `/pause` — только алерты, никаких действий (`/pause 2` — только для кошелька №2);
- `/resume` — снова действовать (`/resume 2`).

### 3. Сначала тестнет

Lighter RH есть в тестнете. Создай ключи с `python setup_key.py --wallet 1 --testnet`, открой позицию со стопом и проверь все сценарии на ненастоящих деньгах.

## Где запускать

Страж должен работать **постоянно**: пока он выключен, он не защищает.

- **Свой компьютер**, если он и так всегда включён: `python guardian.py`.
- **Сервер (VPS)** — надёжнее всего. Подойдёт самый дешёвый, или бесплатный Oracle Cloud Always Free.
  ```bash
  docker build -t lighter-guardian .
  docker run -d --restart=always --env-file .env --name guardian lighter-guardian
  ```
- **Не используй GitHub Actions**: серверы GitHub в США, Lighter может блокировать оттуда торговые запросы, и раз в 6 часов будет пауза без защиты.

Выбирай сервер **не в США**.

## Прокси

У каждого кошелька может быть свой прокси, а общий используется для Telegram и для кошельков без своего:

```
PROXY=http://логин:пароль@общий:порт        # общий (необязательно)
W1_PROXY=http://логин:пароль@хост1:порт     # кошелёк №1
W2_PROXY=http://логин:пароль@хост2:порт     # кошелёк №2
```

Через прокси кошелька идёт весь его трафик к Lighter: данные (REST и WebSocket), проверка ключа и отправка ордеров. Поддерживаются HTTP/HTTPS-прокси. Пароль от прокси в логи и Telegram не попадает: `/wallets` показывает только хост.

Скрипт ключей тоже работает через прокси кошелька: `python setup_key.py --wallet 2 --proxy http://…` (или берёт `W2_PROXY` / `PROXY` из `.env`).

## Важно знать

- Страж — подстраховка, а не замена стопам. Ставь стопы как обычно, лучше связкой TP/SL, привязанной к позиции.
- Рыночное закрытие на тонком стакане может пройти с заметным проскальзыванием. Это сознательный выбор: лучше закрыть хуже, чем не закрыть.
- Сценарий 3 закрывает позицию по цене в стакане, даже если биржевой стоп по mark price ещё не сработал. Если такое поведение не нужно, поставь `SOFT_STOP=alert`.
- Используешь на свой риск. Код открыт: проверь его сам или попроси кого-то, кому доверяешь.

```bash
python -m tests.test_guardian

```

Тесты проверяют все сценарии на симулированных биржах: отмену висящих ордеров, аварийное закрытие, повторы, ложные срабатывания на шпильках, вилку (закрытие, пропорциональная подрезка, исполнение кусками, отсутствие зацикливания), DRY_RUN и паузу.
