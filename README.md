# 🛡 Lighter Guardian

Страж для позиций на **Lighter RH (Robinhood Chain)** и **основном Lighter**. Подстраховывает стоп-лоссы, которые «не сработали», и убирает висящие ордера.

> Это не бот-сервис: каждый запускает **свою копию** со **своим** API-ключом. Все ключи хранятся только у тебя, в зашифрованном виде, и никуда не отправляются. Никому не отправляй свой ключ — в том числе в «удобные» боты.

## Зачем

Частая жалоба: *«стоп-лосс не сработал»*. Обычно причина одна из трёх:

1. **Стоп сработал, но биржа его отменила.** У стоп-заявки есть «худшая цена исполнения». Если в стакане нет ликвидности по такой цене (на тонких pre-IPO это норма), заявка отменяется, а позиция остаётся открытой.
2. **Стоп считается по mark price, а не по цене в стакане.** На pre-IPO mark может отставать: по стакану цена давно за стопом, а триггер так и не сработал. Стоп-лимит может сработать, но повиснуть неисполненным, если цена убежала дальше лимита.
3. **TP и SL поставлены отдельно, а не связкой.** После стопа тейк остаётся висеть и потом срабатывает на новой позиции.

## Что делает страж

| # | Ситуация | Что делает |
|---|---|---|
| 1 | Позиция закрылась (стоп, тейк, вручную) | Отменяет оставшиеся TP/SL и reduce-only ордера по этой паре. Входные ордера (лимитки, стоп-входы, ордера, ждущие родителя) не трогает |
| 2 | Стоп сработал, но биржа его отменила | Сразу закрывает позицию рыночной reduce-only заявкой |
| 3 | Цена в стакане за стопом N секунд, а стоп не исполнился | Закрывает позицию рыночной reduce-only заявкой |
| 4 | Позиция без стоп-лосса | Предупреждает в Telegram (один раз) |
| 5 | **Вилка RH ↔ CORE**: одна нога закрылась | Через 3 секунды закрывает вторую ногу |
| 6 | **Вилка RH ↔ CORE**: одна нога уменьшилась | Подрезает вторую в той же пропорции |

### Вилка (хедж) RH ↔ CORE

Если **в одном кошельке** на Lighter RH и на основном Lighter открыта **одна и та же акция в противоположные стороны** (например, лонг NVDA на RH и шорт NVDA на CORE), страж сам считает это вилкой и пишет «🔗 Вижу вилку».

- **Одна нога закрылась** (по стопу, тейку, ликвидации или вручную) → через **3 секунды** вторая закрывается рыночной reduce-only заявкой. Так ты не остаёшься с голой позицией.
- **Одна нога уменьшилась** → вторая подрезается в той же пропорции. Закрыл 75% лонга на RH → закроется 75% шорта на CORE.
- **Доливка** не трогается: страж просто запоминает новый размер.
- **Пауза 3 секунды** (`HEDGE_DEBOUNCE_SEC`). Отсчёт идёт от последнего изменения ноги: стоп или тейк часто исполняется кусками, и страж ждёт, пока куски закончатся, чтобы подрезать одним разом. Если за эти 3 секунды вторая нога закроется сама — по своему тейку или стопу, — страж её не трогает. Пока идёт пауза, вторая нога стоит без пары: можно поставить и больше, например 10, если хочешь дать второй ноге шанс закрыться по своему тейку.
- Свои подрезки страж не зеркалит обратно, так что цепочки «подрезал → в ответ подрезал» не будет.
- Ноги вилки без стопа не считаются «голыми»: вилка сама себе хедж.
- Одна акция под разными тикерами (SKHYNIX на CORE и SKHY на RH) распознаётся.

Для вилки у кошелька нужны ключи **обеих** бирж. Позиции разных кошельков в вилку не связываются. `/pairs` в Telegram показывает текущие вилки.

Если закрываешь вилку руками, закрой одну ногу, и страж закроет вторую сам. Если хочешь управлять ногами по отдельности, сначала отправь `/pause`.

Закрытие делается с допуском 1% от лучшей цены. Если не исполнилось, повтор с 2% и 3%. Если и так не вышло, приходит громкий алерт «закрой вручную». Все заявки стража **reduce-only**: открыть новую позицию или перевернуть текущую он не может физически.

Каждый сценарий настраивается: `act` — действовать, `alert` — только сообщать, `off` — выключить.

### Режим проверки (DRY_RUN)

По умолчанию `DRY_RUN=true`: страж ничего не отправляет на биржу и только пишет в Telegram, что **сделал бы**. Поработай так день-два, посмотри на сообщения, и только потом ставь `DRY_RUN=false`.

## Установка

Нужен Python 3.10+.

```bash
git clone https://github.com/ogcrypto420/lighter-guardian.git
cd lighter-guardian
pip install -r requirements-setup.txt     # aiohttp, cryptography и eth-account (для создания ключей)
python fetch_signer.py                    # официальный модуль подписи Lighter, с проверкой SHA-256
cp .env.example .env                      # настройки поведения; ключей там нет
```

### 1. Хранилище секретов

Все ключи, адреса, прокси и токен Telegram хранятся в **зашифрованном файле** `guardian.vault`, а не в `.env`.

```bash
python vault.py init
```

Придумай пароль (минимум 10 символов). Он нигде не сохраняется, и восстановить его нельзя: если забудешь, создашь хранилище заново и перевыпустишь ключи.

### 2. Кошельки и API-ключи

Страж следит сразу за несколькими кошельками. Каждый кошелёк получает номер (№1, №2, …), и в сообщениях всегда видно, о каком речь: `NVDA · #1 Основной RH`. Кошелёк на Lighter RH и на основном Lighter один и тот же: номера аккаунтов на обеих биржах страж найдёт сам.

#### Ключ через сайт Lighter (рекомендуется)

Ключ кошелька при этом не покидает твой кошелёк (Robinhood Wallet, MetaMask, Rabby — любой): регистрацию API-ключа он просто подписывает, как обычную транзакцию.

1. Открой сайт Lighter **на компьютере** и подключи кошелёк (Robinhood Wallet — через WalletConnect, QR-кодом с телефона).
2. Меню **Tools → API Keys** → **Generate API Key**.
3. Индекс — **4 или больше**. Индексы 0–3 занимает сам Lighter, включая мобильное приложение: займёшь их — вылетишь с телефона. Не используй этот индекс больше нигде.
4. Подтверди в кошельке. Lighter покажет **Private Key** — это API-ключ. Не сохраняй его в заметки и не делай скриншот: сразу переходи к шагу 5.
5. Запиши кошелёк в хранилище:
   ```bash
   python vault.py wallet
   ```
   Команда спросит номер кошелька, подпись, адрес и API-ключи (ввод скрыт, на экран ключи не выводятся). Ключ можно ввести для одной биржи или для обеих.

Lighter RH и основной Lighter — разные биржи. Для вилки ключ нужен на **обеих**: сделай шаги 1–4 на каждой и введи оба ключа в шаге 5.

Номер аккаунта указывать не нужно: страж найдёт основной аккаунт по адресу. Нужен субаккаунт — впиши его номер, когда команда спросит (виден в Lighter: иконка кошелька справа вверху → Explorer).

#### Ключ скриптом (если у кошелька можно экспортировать приватный ключ)

```bash
python setup_key.py --wallet 1 --name Основной
python setup_key.py --wallet 2 --name Второй --proxy http://логин:пароль@хост:порт
python setup_key.py --wallet 3 --only rh
```

Скрипт сам создаёт ключи для обеих бирж и кладёт их в хранилище. Он спросит пароль хранилища и приватный ключ кошелька (ввод скрыт). Ключ кошелька нужен только чтобы подписать регистрацию: он не сохраняется и в сеть не уходит, туда уходит только подпись. Индекс по умолчанию 4, субаккаунт — флаги `--rh-account` / `--core-account`. Удобно, если ключи надо регистрировать через прокси кошелька.

### 3. Telegram (необязательно)

Создай своего бота у [@BotFather](https://t.me/BotFather) и запиши данные в хранилище:

```bash
python vault.py set TG_TOKEN              # токен бота (ввод скрыт)
python vault.py set TG_CHAT_ID 123456789  # твой chat id (узнать у @userinfobot)
```

Команды бота (отвечает только тебе, чужим не отвечает вообще):
- `/status` — позиции, стопы, тейки, цены, вилки (`/status 2` — только кошелёк №2);
- `/pairs` — вилки RH ↔ CORE (`/pairs 1` — кошелька №1);
- `/wallets` — список кошельков и аккаунтов;
- `/pause` — только алерты, никаких действий (`/pause 2` — только для кошелька №2);
- `/resume` — снова действовать (`/resume 2`).

Без Telegram страж тоже работает: тогда все события пишутся только в лог на твоём компьютере.

### 4. Сначала тестнет

Lighter RH есть в тестнете. Создай ключ на тестнет-версии сайта Lighter, запиши его через `python vault.py wallet` и укажи сеть: `python vault.py set W1_RH_NETWORK robinhood_testnet` (скрипт `setup_key.py --wallet 1 --testnet` пропишет сеть сам). Потом открой позицию со стопом и проверь все сценарии на ненастоящих деньгах.

### 5. Запуск

```bash
python guardian.py
```

Страж спросит пароль хранилища и начнёт работу.

Если в `.env` уже были ключи от старой версии, перенеси их одной командой: `python vault.py import .env`. Ключи переедут в хранилище, а из `.env` будут стёрты. Пока ключи лежат в `.env` открытым текстом, страж **не запустится**.

## Где запускать

Страж должен работать **постоянно**: пока он выключен или компьютер спит, он не защищает.

### Свой компьютер

Если компьютер и так всегда включён: `python guardian.py`, пароль вводится при каждом запуске. Самый приватный вариант: всё только у тебя.

### Сервер (VPS)

Надёжнее по аптайму. Подойдёт самый дешёвый, или бесплатный Oracle Cloud Always Free. Нужен Docker.

Ключ кошелька на сервер **не попадает**: хранилище и ключи создаёшь у себя на компьютере (шаги 1–3 выше), а на сервер копируешь только зашифрованный `guardian.vault`.

```bash
# на сервере, в папке проекта (если ты не root — добавляй sudo)
cp .env.example .env && nano .env                     # настройки поведения
mkdir -p data
# со своего компьютера: scp guardian.vault root@IP-сервера:lighter-guardian/data/
install -m 600 /dev/null data/password.txt && nano data/password.txt   # пароль хранилища, одной строкой
chown -R 10001:10001 data && chmod -R go= data        # читать папку сможет только страж
docker build -t lighter-guardian .
docker run -d --restart=always --name guardian \
  --read-only --cap-drop ALL --security-opt no-new-privileges \
  -v "$PWD/data:/data:ro" --env-file .env lighter-guardian
docker logs -f guardian                               # проверить, что страж запустился
```

В контейнере страж работает от отдельного пользователя без прав администратора, файловая система только для чтения, модуль подписи проверен по SHA-256.

**Без файла с паролем.** Файл нужен, чтобы страж сам поднимался после перезагрузки. Если не хочешь хранить пароль на сервере вообще, не создавай `data/password.txt` и запусти так:

```bash
docker run -dit --restart=always --name guardian \
  --read-only --cap-drop ALL --security-opt no-new-privileges \
  -v "$PWD/data:/data:ro" --env-file .env lighter-guardian
docker attach guardian      # введи пароль и Enter (ввод скрыт), потом Ctrl+P, Ctrl+Q — выйти, не останавливая
```

Тогда пароль есть только в памяти. Но после каждой перезагрузки сервера страж ждёт пароль и **не защищает**, пока ты снова не введёшь его через `docker attach guardian`.

Изменить хранилище (новый кошелёк, другой прокси) проще у себя на компьютере: поменяй, снова скопируй `guardian.vault` в `data/`, повтори `chown` и `chmod` и выполни `docker restart guardian`.

### Не GitHub Actions

Ключи пришлось бы отдать в чужую инфраструктуру, и раз в 6 часов была бы пауза без защиты.

## Прокси

У каждого кошелька может быть свой прокси, а общий используется для Telegram и для кошельков без своего. Прокси тоже хранятся в хранилище:

```bash
python vault.py set PROXY        # общий (необязательно)
python vault.py set W1_PROXY     # кошелёк №1
python vault.py set W2_PROXY     # кошелёк №2
```

Формат: `http://логин:пароль@хост:порт`. Через прокси кошелька идёт весь его трафик к Lighter: данные (REST и WebSocket), проверка ключа и отправка ордеров. Системные настройки прокси (`HTTPS_PROXY` и т.п.) страж игнорирует, работают только заданные здесь. Пароль от прокси в логи и Telegram не попадает.

## 🔒 Безопасность

### Что где хранится

| Данные | Где | Защита |
|---|---|---|
| API-ключи, адреса кошельков, прокси, токен Telegram | `guardian.vault` у тебя | AES-256-GCM, ключ из пароля через scrypt; файл с правами 600 |
| Приватный ключ кошелька | в твоём кошельке | при ключе через сайт страж его не видит вообще; в `setup_key.py` вводится один раз и не сохраняется |
| Пароль хранилища | нигде (или в `data/password.txt` на сервере) | файл с паролем — только для автозапуска на сервере, и он необязателен |
| Настройки поведения | `.env` | ничего секретного; страж не запустится, если найдёт там ключи |

### Куда страж ходит в сеть

Только на эти адреса, остальное блокируется в коде (белый список, только https/wss):

- `api.rh.lighter.xyz`, `mainnet.zklighter.elliot.ai` (и их тестнеты) — данные аккаунта и отправка ордеров;
- `api.telegram.org` — уведомления (если Telegram настроен).

Никакой телеметрии, аналитики, сторонних серверов и автообновлений нет. Скачивание модуля подписи (`fetch_signer.py`) идёт один раз с `raw.githubusercontent.com` — официальный репозиторий Lighter, зафиксированный коммит, проверка SHA-256.

### Что видят другие

- **Lighter** видит твои позиции и ордера: это биржа, иначе никак. API-ключ туда **не передаётся**: транзакции подписываются у тебя, на биржу уходит только подпись. Для проверки ключа используется временный токен на 10–60 минут.
- **Прокси** видит только то, что ты подключаешься к Lighter или Telegram. Содержимое зашифровано TLS от тебя до биржи, ни ключей, ни данных прокси не видит.
- **Telegram** видит текст уведомлений: переписка с ботами не шифруется сквозным шифрованием. Поэтому по умолчанию `TG_DETAIL=short` — в уведомлениях нет размеров позиций, цен и номеров аккаунтов, только тикер и что произошло. `TG_DETAIL=minimal` скрывает ещё и тикеры, `TG_DETAIL=full` показывает всё. Это касается и ответов на `/status`.

### Защита программы

- **Минимум чужого кода рядом с ключами.** Страж не использует SDK Lighter с его ~25 зависимостями: только `aiohttp` и `cryptography`, плюс официальный модуль подписи Lighter.
- **Модуль подписи проверяется по SHA-256** при каждом запуске. Подменённый файл не загрузится.
- **Модуль подписи работает без сети.** Ему даже не передаётся адрес биржи. Проверено трассировкой системных вызовов: при генерации ключа и подписи — ноль сетевых соединений.
- **Секреты вымарываются** из логов, текстов ошибок и сообщений Telegram: ключи, токены, пароли прокси.
- **Дампы памяти отключены**, а на Linux другие программы (кроме администратора) не могут читать память стража.
- Все создаваемые файлы доступны только владельцу.

### Чего защита не покрывает

- Если на компьютере или сервере, где работает страж, уже сидит вирус с твоими правами или правами администратора, он может дождаться, пока ты введёшь пароль, или прочитать память. Запускай стража на чистой машине, которой доверяешь.
- Если пароль лежит в `data/password.txt` рядом с хранилищем, то тот, кто получил полный доступ к серверу, получит и ключи. Шифрование тогда защищает от случайных утечек (копии хранилища, бэкапы, синхронизация в облако), а не от взлома сервера.
- Сервер — чужой компьютер: хостинг технически может заглянуть в его диск и память. Самый приватный вариант — свой компьютер, на сервере — запуск без файла с паролем.
- Слабый пароль можно подобрать перебором, если украдут файл хранилища. Используй длинный: 4–5 случайных слов.
- API-ключ даёт право торговать. Вывести деньги им можно только на твой же кошелёк, но испортить позицию — можно. Держи на торговом аккаунте только нужную маржу.

## Важно знать

- Страж — подстраховка, а не замена стопам. Ставь стопы как обычно, лучше связкой TP/SL, привязанной к позиции.
- Рыночное закрытие на тонком стакане может пройти с заметным проскальзыванием. Это сознательный выбор: лучше закрыть хуже, чем не закрыть.
- Сценарий 3 закрывает позицию по цене в стакане, даже если биржевой стоп по mark price ещё не сработал. Если такое поведение не нужно, поставь `SOFT_STOP=alert`.
- Используешь на свой риск. Код открыт: проверь его сам или попроси кого-то, кому доверяешь.

```bash
python -m tests.test_guardian
python -m tests.test_hedge
python -m tests.test_wallets
python -m tests.test_security
python -m tests.test_setup
```

Тесты проверяют все сценарии на симулированных биржах: отмену висящих ордеров, аварийное закрытие, повторы, ложные срабатывания на шпильках, вилку (закрытие, пропорциональная подрезка, исполнение кусками, отсутствие зацикливания), DRY_RUN и паузу. Отдельно проверяется безопасность: шифрование и защита хранилища от подмены, вымарывание секретов, белый список адресов, проверка модуля подписи, формат транзакций и то, что ключи не попадают ни на экран, ни в сеть.
